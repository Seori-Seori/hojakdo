# Hojakdo Watch Face

갤럭시 워치용 한국 민화 **호작도(鵲虎圖)** 콘셉트 워치페이스다.

> 손목 위에서 살아 움직이는 호작도 한 점.

소나무 가지를 시침과 분침으로 사용하고, 큰 까치와 작은 까치가 절대 시간에 맞춰 그림 속을 이동한다. 움직임은 부드러운 캐릭터 애니메이션보다 피영극처럼 빠르게 움직이고 오래 멈추는 절제된 리듬을 지향한다.

애니메이션과 장면 구현의 최상위 기준은 [`docs/animation-blueprint.md`](docs/animation-blueprint.md), 자산 분리 상태는 [`docs/asset-extraction-plan.md`](docs/asset-extraction-plan.md)에서 관리한다.

## 현재 단계

> **V4.2 상단 판독성 개선 후보 완료 / 16개 AGIF·실시간 WFF·AOD 연결 완료**

V1~V3.1 결과는 회귀 비교용으로 보존했다. V4는 승인된 V3.1 구도를 실제 리소스 전용 Watch Face Format v1 프로젝트에 연결했고, V4.1은 손목에서 두 바늘이 즉시 구분되도록 시침 유효 길이를 92px로 줄이고 분침을 126px로 늘렸다. V4.2는 실시간 시각을 상단 중앙으로 옮겨 36px로 키우고, 날짜와 요일을 그 아래 한 줄로 합쳤다. 네 종류의 바늘 착석점과 비행·착지 끝점은 V4.1의 동일 길이 변환식을 유지한다.

현재 완료된 범위:

- 43분 절대 사이클과 첫 2분 `HIDDEN`
- 큰 까치·작은 까치의 엄격한 교대와 한 장면 한 마리 원칙
- 분침 직접, 시침→분침 환승, 매화 걷기 경로
- 실제 착지 완료 시각 기준 하루 평균 약 6회의 2사분면 바늘 착석
- 365일 검증 범위에서 하루 4~8회, 평균 5.997회
- 큰 까치의 오른쪽 등장, 발 기준점 고정 최종 0.85728배 렌더링, 느린 고개 동작, 뒤보기·복귀 방향 동작, 접은 날개 점프 퇴장
- 작은 까치의 고개 살피기·매화 보기·다음 목표 확인, 3회 중 2회의 귀 두 번 쪼기
- V3 작은 까치 퇴장은 승인된 고정 비행 한 장을 사용하며 날갯짓 없이 까치 전체를 오른쪽으로 이동
- 모든 이동 구간에서 실제 수평 이동량에 맞춘 좌우 방향, 호랑이 착지 뒤 작은 홉 전환
- 작은 까치가 시침·분침의 서로 다른 실제 끝점에 발과 가지를 약 2px 겹쳐 착지
- 호랑이 몸통·머리·눈동자를 하나의 그룹으로 묶어 94%로 축소하고 턱·목 알파 복원 유지
- 배터리 `0~15 / 16~35 / 36~55 / 56~80 / 81~100%`에 대응하는 매화 5단계 정적 교체
- 배터리 아이콘·숫자 퍼센트 유지, 피어나는 전환 애니메이션 없음
- 상단 중앙의 큰 디지털 시각과 한 줄짜리 날짜·요일 표시
- 배경에 구워져 있던 시각·날짜·요일 잔상과 중앙 구름선·배터리 픽셀 제거 후 WFF 실시간 데이터로 교체
- 날짜 뒤 옅은 구름 잔상 좌표를 배경에서 복원하고, `(188, 272)~(270, 294)` 한지 덮개는 배경 바로 위·시침과 분침 아래에 배치
- 94% 호랑이 뒤에 남은 원래 100% 뒷다리 외곽선을 승인된 94% 소스로 교체
- 배터리 매화와 소나무·호랑이 전경 마스크를 모두 시침·분침 아래에 두어 어느 각도에서도 두 바늘이 사라지지 않게 유지
- 매화 걷기 까치와 대기 자세를 가지·배터리 꽃보다 위에 렌더해 만개 상태에서도 전 프레임 표시
- V4.1 시침 92px·분침 126px, 시침/분침 길이비 약 0.73과 굵기 대비로 즉시 판독
- 상단 실시간 표시는 바늘·캐릭터·전경 가림막보다 위에 렌더해 가독성 고정
- 시각은 `x=225`, `y=38`, 36px이며 날짜·요일은 `y=79`, 13px 한 줄로 정렬
- 상단 한지 여백에 고립되어 있던 솔잎 조각 좌표 `(282, 158)~(306, 181)`을 종이 질감으로 복원
- 작은 까치 고정 비행 런타임 자산을 138×107에서 70×54로 축소해 정적 자세와 크기 연속성 확보
- 호랑이 위 까치는 머리 레이어보다 위에 두고 발 기준점을 큰 까치 `(335, 233)`, 작은 까치 `(340, 241)`로 고정해 작은 까치 발을 머리에 6px 겹침
- 큰·작은 까치 정적 자세 6종과 매화·소나무·호랑이 몸 전경 가림막 3종 완성
- 큰 까치 7개, 작은 까치 8개, 호랑이 1개의 AGIF 16개와 원본 프레임·메타데이터·썸네일 완성
- 16개 AGIF를 43분 무상태 WFF `Condition` 시간표에 연결
- 실시간 `HH:mm`, `MM.DD`, 요일, 배터리 퍼센트와 배터리 5단계 매화 연결
- 시침·분침 착석 까치를 회전 그룹과 역회전 캐리어에 연결
- 정적 머리와 반응 AGIF를 배타적으로 전환해 호랑이 머리 선행, 눈동자 후행, 작은 반동과 중립 복귀를 선명하게 유지
- AOD에서 까치와 모든 세부 애니메이션은 숨기고 현재 매화 단계는 낮은 밝기로 유지
- 결정성·교대·경로 고정·자정 연속성·빈도·AOD·쪼기·고정 비행·배터리 경계·자산 메모리 자동 테스트
- V1~V4.2 합계 51개 자동 테스트 통과
- 압축 해제 추정 메모리: 대화형 11.61MiB, AOD 정적 자산 5.82MiB

V4.2의 소스·자산·WFF 연결과 정적 검증은 완료됐다. 현재 작업 환경에는 Android SDK와 Gradle 8.13 배포본이 없고 외부 배포본 다운로드도 차단되어 APK 조립과 Wear OS 에뮬레이터 렌더 검증은 수행하지 못했다. Android Studio 또는 CI에서 `:watchface:assembleDebug`와 실기기 검수를 통과하면 배포 후보로 승격한다.

## 승인된 핵심 규칙

### 절대 시간과 교대

```text
43분 사이클
→ 첫 2분 HIDDEN
→ 큰 까치 또는 작은 까치 한 마리
→ 경로 완료
→ 오른쪽 화면 밖까지 퇴장
→ 다음 사이클에서 반대 까치
```

- 자정에 사이클을 초기화하지 않는다.
- 사이클 시작 때 경로와 바늘을 결정하고 끝까지 바꾸지 않는다.
- 화면을 다시 켜도 같은 시각에는 같은 까치·경로·거시 위치를 복원한다.
- `EXIT_RIGHT`는 공통 논리 상태이며 큰 까치는 점프, 작은 까치는 고정 비행 이미지로 교체한 뒤 날갯짓 없이 전체 스프라이트를 오른쪽으로 이동한다.

### 경로

```text
분침 직접: 소나무 → 분침 → 호랑이 → 오른쪽 퇴장
시침 환승: 소나무 → 시침 → 분침 환승 → 호랑이 → 오른쪽 퇴장
매화 경로: 매화 → 한 칸씩 이동 → 호랑이 → 오른쪽 퇴장
```

큰 까치와 작은 까치를 특정 바늘 전용으로 고정하지 않는다. 큰 까치는 안쪽의 두꺼운 착석점과 시침에 조금 더 어울리고, 작은 까치는 바깥쪽의 얇은 착석점과 분침 직접 경로에 조금 더 어울리도록 가중치와 좌표만 다르게 둔다.

### 세부 행동

- 큰 까치: 긴 체류 중 느린 고개 동작 1회, 구도상 필요할 때 상체 뒤보기 최대 1회
- 작은 까치: 긴 체류의 약 25%·50%·75% 지점에 최대 3개의 상체 행동
- 이동 중 몸 방향은 실제 수평 이동 방향을 따르고, 작은 까치는 호랑이 착지 뒤 귀 쪽으로 홉 전환
- 작은 까치가 호랑이 위에 앉는 장면 3회 중 2회에는 귀를 빠르게 두 번 쪼음
- 추가 행동 중 발 기준점은 고정하고 상체만 움직임
- 한 사이클의 호랑이 반응은 정확히 1회이며, 귀 쪼기 장면에서는 쪼기가 유일한 반응 원인

### AOD

- 모든 AGIF와 까치를 숨김
- 호랑이 세부 반응 레이어를 숨김
- 현재 배터리 구간의 매화 정적 단계는 낮은 밝기로 유지
- 시간 표시와 필요한 최소 윤곽만 유지

## 자산 상태

- 큰 까치: 승인된 깨끗한 기반 마스터 사용
- 작은 까치: 가지·붉은 노리개가 없는 V2.1 투명 기반 마스터 사용
- 작은 까치 퇴장: 승인 원본, `magpie_small_flight_right_v31_master.png` 투명 정렬 마스터, `magpie_small_flight_right_v31.png` 런타임 스프라이트 완료
- 호랑이: 턱·목 알파를 복원한 V2.2 머리와 94% 눈동자 분리 레이어 사용
- 매화: 빈 가지가 포함된 V2.3 기본 배경 1장과 누적 꽃 레이어 5단계 사용

## Android Studio 실행

1. 저장소 루트 폴더를 Android Studio에서 연다.
2. Gradle Sync를 실행한다.
3. Wear OS API 33 이상 에뮬레이터 또는 기기를 선택한다.
4. `watchface` 모듈을 실행한다.

현재 `watchface`는 V4.2 자산과 실시간 WFF 로직을 사용한다. 설치 전 검수는 Android Studio에서 Gradle Sync와 `assembleDebug`를 실행한 뒤 API 33 이상 Wear OS 에뮬레이터 또는 실기기에서 대화형·AOD 전환, 16개 전환 슬롯, 상단 두 줄 텍스트 기준선을 확인한다.
