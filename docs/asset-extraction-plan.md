## 2. 1단계 세부 작업 결과

### 2.1 저장소 기준점

- 브랜치: `main`
- 기준 원본: `assets/hojakdo_basic_416.png`
- 기존 분리 예시: `assets/layers/mvp/*.png`
- 원본 크기: 1254×1254 RGB
- WFF 크기: 450×450
- 원본 → 논리 배율: `0.358851674641`
- 논리 → 원본 배율: `2.786666666667`

### 2.2 기존 예시가 레이어를 분리한 방식

`hour_branch`, `hour_magpie`, `minute_branch`, `minute_magpie`, `tiger_head`, `tiger_pupils`의 알파를 제거하고 원본과 비교한 결과는 모두 `AE=0`이었다.

즉, 기존 예시는 다음 구조다.

```text
원본 1254×1254 RGB 전체를 그대로 보유
+ 대상 부위만 보이게 하는 알파 마스크
= 원본 위치가 보존된 분리 레이어
```

이 방식에서 **원본 정렬을 유지한 점은 계승**한다. 다만 완전히 투명한 영역에도 원본 RGB 전체가 남아 각 희소 레이어가 약 3MB인 점은 계승하지 않는다. 새 마스터는 투명 픽셀의 RGB를 0으로 정규화한다.

`clean_background.png`는 예외다. 이것은 알파 마스크 레이어가 아니라 움직이는 부위를 메운 완전 불투명 배경이다.

### 2.3 실측 인벤토리

| 기존 파일 | 실제 내용 | 의미 역할 | 원본 알파 경계 `w×h+x+y` | 450 논리 경계 `x,y,w,h` | 알파 픽셀 | 확인된 문제 |
|---|---|---|---|---|---:|---|
| `hour_branch.png` | 오른쪽 짧은 바늘 가지 | 현재 시침 가지 | `232×178+637+383` | `228.589,137.440,83.254,63.876` | 8,871 | 의미상 문제 없음 |
| `hour_magpie.png` | 오른쪽 작은 까치 | **작은 까치** | `102×238+830+317` | `297.847,113.756,36.603,85.407` | 7,344 | 가지 조각과 붉은 노리개 포함 |
| `minute_branch.png` | 왼쪽 긴 바늘 가지 | 현재 분침 가지 | `210×237+409+315` | `146.770,113.038,75.359,85.048` | 6,172 | 의미상 문제 없음 |
| `minute_magpie.png` | 왼쪽 큰 까치 | **큰 까치** | `220×257+292+144` | `104.785,51.675,78.947,92.225` | 18,464 | 발 아래 착석 가지 조각 포함 |
| `tiger_head.png` | 분리된 호랑이 머리 | 호랑이 머리 | `257×262+822+601` | `294.976,215.670,92.225,94.019` | 37,257 | 눈동자는 별도 레이어 |
| `tiger_pupils.png` | 양쪽 눈동자 | 호랑이 반응 후보 | `127×94+858+681` | `307.895,244.378,45.574,33.732` | 3,357 | 두 눈이 한 레이어에 묶임 |

알파 픽셀 수는 알파가 0보다 큰 원본 픽셀의 개수다. 반투명 가장자리를 강제로 이진화하지 않는다.

### 2.4 큰·작은 까치 매핑 결정

```text
기존 minute_magpie.png → magpie_large
기존 hour_magpie.png   → magpie_small
```

기존 이름은 까치 종류가 아니라 MVP에서 붙어 있던 바늘을 나타낸다. 따라서 기존 파일과 WFF 참조는 이름을 바꾸지 않는다. 새로 만드는 자산만 의미 기반 이름을 사용한다.

현재 WFF의 캐리어 피벗은 임시 발 기준점 후보로만 기록한다.

| 까치 | 현재 캐리어 피벗(논리) | 원본 환산값 | 상태 |
|---|---:|---:|---|
| 큰 까치 | `(159, 118)` | `(443.080, 328.827)` | 실제 발 중앙 재검증 필요 |
| 작은 까치 | `(305, 143)` | `(849.933, 398.493)` | 가지·노리개 제거 후 재검증 필요 |

두 까치 레이어의 보이는 영역은 각각 하나의 연결 성분으로 붙어 있다. 큰 까치의 발과 가지, 작은 까치의 발·가지·노리개를 연결 성분 삭제만으로 나눌 수 없으므로 접촉부를 직접 편집해야 한다.

### 2.5 현재 원본으로 바로 만들 수 없는 것

원본에는 큰 까치와 작은 까치가 각각 한 가지 착석 자세로만 존재한다. 따라서 다음을 구분한다.

- `perch_hand`: 기존 착석 자세를 정리해 만들 수 있음
- `perch_tiger`: 초기에는 같은 자세를 재사용할 수 있으나 발과 머리 접촉부를 검수해야 함
- `walk_idle`: 지면용 발 모양이 필요하므로 단순 분리만으로 완료할 수 없음

그러므로 정적 자세 6종을 파일 복사로 채우지 않는다. 먼저 깨끗한 까치 마스터 2종을 만든 뒤, 실제로 달라야 하는 자세만 파생 제작한다.

## 3. 새 자산의 추출 규격

### 3.1 원본 정렬 마스터

- 캔버스: 1254×1254 RGBA
- 위치: 원본과 동일한 좌표
- 배경: 완전 투명
- 완전 투명 픽셀: RGBA `(0,0,0,0)`로 정규화
- 가장자리: 원본의 반투명 안티앨리어싱 보존
- 금지: 가지, 노리개, 배경 얼룩을 캐릭터 마스터에 포함
- 금지: 기존 `assets/layers/mvp` 파일 덮어쓰기

### 3.2 런타임 크롭

- 원본 정렬 마스터에서 자동 생성
- 정적 자세는 실제 알파 경계에 원본 기준 12px 안전 여백을 기본 적용
- 캔버스 밖 여백은 추가하지 않음
- 크롭의 원본 위치 `cropX`, `cropY`를 메타데이터에 기록
- 발 기준점은 크롭 좌표와 450 논리 좌표를 함께 기록
- 애니메이션은 날개·꼬리의 전체 프레임 합집합 경계를 사용하며 여백을 별도 확정

### 3.3 파일 역할

```text
assets/layers/mvp/
  현재 실행 중인 MVP 보존

assets/layers/source/
  새 원본 정렬 마스터와 실측 manifest

빌드 생성 디렉터리/
  450 기준 축소·크롭·반전 런타임 자산
```
