# 호작도 워치페이스 애니메이션 구현 기준서

> 문서 상태: 프로젝트 최상위 애니메이션 기준서
>
> 구현 기준: Watch Face Format(WFF) v1, 논리 좌표계 450×450
>
> 원칙: 이 문서와 임시 예시·기존 README가 충돌하면 이 문서를 우선한다.

## 1. 핵심 목표

> 손목 위에서 살아 움직이는 호작도 한 점.

현재 구현된 시계 바늘 MVP 위에 큰 까치, 작은 까치, 호랑이 반응을 추가한다.

까치는 화면을 켤 때마다 처음부터 등장하는 캐릭터가 아니다. 현재 날짜와 시각을 입력으로 사용해:

1. 현재 진행 중인 논리 장면을 결정하고,
2. 그 장면의 거시 진행 위치를 계산하며,
3. 해당 시점의 까치 종류·경로·바늘·위치·상태를 표시한다.

같은 날짜의 같은 분에 화면을 다시 열면 다음 값은 같아야 한다.

- 까치 종류
- 선택 경로
- 선택 바늘
- 거시 위치와 논리 상태
- 다음 장면 결정값
- 호랑이 반응 여부

짧은 AGIF의 재생 프레임은 이 결정성 보장의 예외다. WFF는 임의 시점의 AGIF 프레임으로 탐색할 수 없으므로, 전환 상태가 다시 보일 때 동일한 짧은 몸동작이 처음부터 한 번 재생될 수 있다. 이 재생은 까치의 거시 좌표·경로·상태를 바꾸지 않는다.

---

## 2. WFF 구현 모델

현재 프로젝트는 `android:hasCode="false"`인 리소스 전용 WFF 워치페이스다. Kotlin 런타임 상태 저장이나 일반적인 객체형 상태 머신을 사용하지 않는다.

문서에서 말하는 상태 머신은 실제로 다음과 같은 **무상태 시간표 계산기**를 의미한다.

```text
현재 날짜와 분
→ 절대 타임라인 값 계산
→ 장면 주기와 고정 난수 계산
→ 현재 상태·까치·경로·바늘·위치 계산
→ 다음 장면 결정값 계산
```

개념식:

```text
timelineMinute =
    YEAR 기반 값
    + DAY_OF_YEAR × 1440
    + HOUR_0_23 × 60
    + MINUTE
```

실제 식은 WFF v1 표현식이 지원하는 연산 안에서 작성한다. `YEAR`를 포함해 해마다 완전히 같은 일정이 반복되는 것을 피한다.

### 용어 규칙

- `상태`: 저장된 값이 아니라 현재 시각으로 계산된 논리 상태
- `예약`: 런타임 저장이 아니라 다음 장면 결정값의 선계산
- `고정 난수`: 날짜·장면 순번을 산술식으로 섞은 결정적 의사난수
- `코드`: 우선 WFF 표현식·Condition·Transform과 빌드 시 자산 생성 로직을 뜻함

WFF 버전 변경이나 Kotlin 기반 구조 전환은 사용자 승인 없이 진행하지 않는다.

---

## 3. 역할 분리

### WFF 표현식·조건식·Transform이 담당할 부분

- 현재 논리 상태
- 까치 종류
- 이동 경로
- 시작점과 도착점
- 바늘 선택
- 까치의 거시 좌표
- 장면 진행 구간
- 다음 장면 결정값
- 좌우 반전
- 렌더링 슬롯과 레이어 표시 여부
- 날짜·시간 기반 고정 난수
- 상태 전환 시점

### AGIF가 담당할 부분

- 날갯짓
- 착지
- 한 걸음
- 짧은 점프
- 퇴장 자세
- 호랑이의 짧은 반응

실제 장거리 좌표 이동은 AGIF 캔버스에 굽지 않는다. AGIF는 짧은 몸동작만 표현하고, 출발점·도착점·경로 이동은 WFF Transform이 담당한다.

## 4. 움직임 스타일

디즈니식으로 부드럽고 유연한 애니메이션을 지향하지 않는다. 중국 피영극이나 그림자 인형극처럼 조금 뻣뻣하고 절제된 움직임을 사용한다.

```text
빠른 움직임
→ 짧은 정지
→ 작은 반동
→ 긴 정지
```

- 관절이 나뉘어 움직이는 듯한 느낌
- 빠르게 움직인 뒤 정확히 멈춤
- 착지 시 아주 짧은 반동
- 정지 시간이 움직임보다 길어야 함
- 과도한 스쿼시·스트레치 금지
- 3D 캐릭터처럼 부드러운 회전과 흔들림 금지
- 초기 버전에서 반복 대기 애니메이션 금지

## 5. 필수 움직임 자산 11개

11개는 초기 완성에 필요한 최소 세트이며 삭제하지 않는다.

### 큰 까치 5개

#### `magpie_large_fly_pine_to_hand.agif`

- 상태: `SPAWN_PINE`, `FLY_PINE_TO_HAND`
- 역할: 소나무 뒤에서 나와 선택된 바늘의 착석점 바로 위까지 이동
- 시작: 몸 일부가 소나무에 가려지고 날개가 접히거나 낮아짐
- 종료: 발을 내밀고 착지 준비
- 몸이 먼저 나오고 날개가 뒤늦게 펼쳐짐
- 날갯짓 1~2회, 짧고 끊기는 동작
- 이동 경로는 WFF Transform이 담당

#### `magpie_large_land_on_hand.agif`

- 상태: `LAND_ON_HAND`, 종료 후 `PERCH_HAND`
- 발이 먼저 닿고 몸이 한 번 눌린 뒤 작은 반동으로 정지
- 꼬리와 머리가 조금 늦게 따라옴
- 모든 프레임에서 발 기준점 유지
- 바늘을 뚫거나 공중에 뜨지 않음

#### `magpie_large_walk_step.agif`

- 상태: `WALK_FROM_PLUM`
- 한 분의 위치 전환 때 한 번만 재생
- 한 걸음이 끝나면 다음 분까지 완전히 정지
- 실제 한 칸 좌표 이동은 WFF가 담당
- 시작 자세와 종료 자세는 같은 걷기 정지 자세로 자연스럽게 연결

#### `magpie_large_hop_to_tiger.agif`

- 상태: `LAND_ON_TIGER`
- 바늘 또는 매화 걷기 종점에서 호랑이 머리로 짧게 점프
- 몸을 낮추고 힘을 모은 뒤 날개를 짧게 펼치고 착지
- 장거리 비행이 아닌 홉
- 초기에는 바늘·지면 경로가 자산을 공유하며, 부자연스러우면 분리

#### `magpie_large_fly_out_right.agif`

- 상태: `FLY_OUT_RIGHT`
- 오른쪽을 보고 몸을 낮춘 뒤 튀어 오르며 화면 밖으로 퇴장
- 화면 경계에서 갑자기 사라지지 않음
- 완료 후 `HIDDEN`

### 작은 까치 5개

#### `magpie_small_fly_pine_to_hand.agif`

- 작은 체형 고유의 날개 비율과 발 기준점 사용
- 큰 까치 자산의 단순 축소 금지
- 큰 까치보다 짧고 가벼운 날갯짓

#### `magpie_small_land_on_hand.agif`

- 큰 까치보다 착지 반동이 작음
- 좁은 가지 끝에 자연스럽게 착석
- 착지 후 화면 안쪽 또는 호랑이 방향을 보도록 기준점 중심 반전 가능

#### `magpie_small_walk_step.agif`

- 1분마다 한 칸 이동할 때 한 번 재생
- 큰 까치보다 작은 보폭
- 종종거리거나 반복 걷는 현대식 캐릭터 동작 금지

#### `magpie_small_hop_to_tiger.agif`

- 호랑이 귀 근처나 머리 가장자리의 좁은 착석점 사용
- 날개를 크게 펄럭이지 않는 짧고 가벼운 점프
- 귀와 머리 레이어를 뚫지 않도록 발 기준점 유지

#### `magpie_small_fly_out_right.agif`

- 큰 까치보다 조금 빠른 퇴장 가능
- 실제 이동 거리는 WFF가 담당
- 화면 밖까지 이동 후 `HIDDEN`

### 호랑이 1개

#### `tiger_reaction.agif`

- `LAND_ON_TIGER` 종료 직후 일부 장면에서만 재생
- 반응 여부는 날짜·장면 기반 고정 난수로 결정
- 초기 버전은 귀 한 번 또는 눈 한 번 중 하나만 구현
- 가능하면 호랑이 전체가 아닌 귀·눈 주변의 작은 크롭 자산으로 제작
- 전체 머리 흔들림, 여러 부위 동시 과장, 1초 이상 반복 금지

## 7. 애니메이션 원본 구조와 메타데이터

AGIF 바이너리만 원본으로 보관하지 않는다.

```text
assets/animation_src/
  magpie_large_land_on_hand/
    frame_00.png
    frame_01.png
    ...
    metadata.json
```

`metadata.json` 필수 항목:

```text
fps
anchorX
anchorY
cropX
cropY
cropWidth
cropHeight
facing
startPose
endPose
loopCount
```

- AGIF는 원본 프레임과 메타데이터에서 생성
- 모든 프레임의 캔버스 크기와 기준점 일치
- 마지막 프레임은 대응 정적 PNG와 자연스럽게 연결

## 8. 논리 상태 목록

```text
HIDDEN
SPAWN_PINE
FLY_PINE_TO_HAND
LAND_ON_HAND
PERCH_HAND
RIDE_HAND
SPAWN_PLUM
WALK_FROM_PLUM
LAND_ON_TIGER
PERCH_TIGER
FLY_OUT_RIGHT
```

이 상태는 저장하지 않고 현재 시각으로 계산한다.

### 정적 상태

- `HIDDEN`: 이미지 없음
- `PERCH_HAND`: 정적 바늘 착석 자세. 렌더링은 `RIDE_HAND`와 공유 가능
- `RIDE_HAND`: 바늘을 따라 이동하고 바늘 회전만큼 역회전해 수직 유지
- `PERCH_TIGER`: 호랑이 머리 위 정적 자세
- `SPAWN_PLUM`: 매화 가림막 뒤에서 몸 일부 표시
- `SPAWN_PINE`: 소나무 가림막 뒤 시작 자세. 비행 첫 부분이 등장 연출을 겸함

## 10. 장면 지속시간과 템포

정확한 값은 좌표 측정과 에뮬레이터 검증 후 확정한다. 아래 값은 초기 튜닝 기준이며 절대 규칙이 아니다.

| 구분 | 초기 목표 |
|---|---:|
| 짧은 AGIF | 0.4~1.2초 |
| 매화 전체 경로 | 약 7~10분 |
| 분침 탑승 경로 | 대략 20~45분 |
| 시침 장기 경로 | 대략 5~8시간, 하루 최대 1회 후보 |
| 호랑이 머리 체류 | 추후 구도 검증 후 결정 |

바늘 후보는 점수뿐 아니라 호랑이까지의 예상 도착시간을 계산해야 한다.

```text
etaToTiger
maxRideDuration
isLongTableau
longTableauCountForDay
```

시침 장기 장면을 유지할지, 더 짧은 별도 하차 규칙을 만들지는 실제 하루 시뮬레이션을 보고 확정한다.

## 11. 바늘 경로 선택

기본 후보:

- 화면 좌상단 2사분면에 위치
- 소나무에서 자연스럽게 접근 가능
- 까치 크기에 맞는 착석 공간 보유
- 호랑이 방향으로 접근하거나 의도한 장기 장면에 적합
- 착석점이 화면 밖으로 잘리지 않음

```text
분침만 적합 → 분침
시침만 적합 → 시침
둘 다 적합 → 자연스러움·도착시간·반복 위치 점수 비교
둘 다 부적합 → 매화 경로
```

기존 점수 숫자는 확정 규칙이 아니라 튜닝 예시이므로 본 기준서에 고정하지 않는다. 실제 점수는 별도 튜닝 표에서 관리한다.

- 큰 까치를 시침 전용으로 고정하지 않음
- 작은 까치를 분침 전용으로 고정하지 않음
- 현재 파일명의 `hour`, `minute`를 논리적 전용 관계로 해석하지 않음

## 12. 바늘에서 호랑이로 이동

다음을 함께 확인한다.

- 현재 상태가 `RIDE_HAND`
- 까치 발과 호랑이 착석점 사이 거리가 가까움
- 바늘이 호랑이 방향으로 접근 중
- 대략 4시 30분~5시 30분 방향
- 다른 이동 전환 중이 아님
- 화면 구도가 자연스러움

조건이 충족돼도 현재 분의 중간에 상태를 갑자기 바꾸지 않는다.

```text
현재 RIDE_HAND 구간 유지
→ 다음 구간의 LAND_ON_TIGER 결정값 계산
→ 구간 경계에서 hop_to_tiger 재생
```

## 13. 매화 걷기 경로

매화는 착석지가 아니라 출입구다.

초기 예시:

```text
1분: 매화 뒤에서 얼굴 일부
2분: 몸이 더 드러남
3분: 첫 한 걸음
4분: 소나무 아래 통과
5분: 호랑이 등 뒤 접근
6분: 호랑이 머리 아래 도착
7분: 호랑이 머리로 점프
```

이 좌표와 분 수는 정적 레이어 분리 후 직접 조정한다.

- 1분마다 위치 한 칸 이동
- `walk_step`은 한 번만 재생
- 나머지 시간은 정지
- 반복 걷기 금지
- 도중에 좋은 바늘이 생겨도 경로 변경 금지
- 시작한 매화 장면은 끝까지 완료

---

## 14. 큰 까치와 작은 까치 교대

```text
큰 까치 → 퇴장 → 작은 까치 → 퇴장 → 큰 까치
```

- 동시에 두 마리 표시 금지
- 현재 까치의 퇴장 완료 뒤 다음 까치 등장
- 큰 까치는 넓은 착석점과 호랑이 머리 중앙에 가중치
- 작은 까치는 좁은 착석점과 귀 근처에 가중치
- 다음 출연 구간이 와도 현재 까치가 남아 있다면 먼저 `FLY_OUT_RIGHT`

---

## 15. 현재 시각 복원과 AGIF 재생 정책

잘못된 방식:

```text
화면 켜짐 → 무조건 SPAWN부터 시작
```

올바른 거시 복원:

```text
현재 날짜와 분
→ 장면 주기 계산
→ 까치·경로·바늘·상태·좌표 계산
→ 해당 정적 자세 또는 전환 그룹 표시
```

AGIF 정책:

- `loopCount=1`, 무한 반복 금지
- 전환 상태가 화면에 나타날 때 동일한 짧은 동작이 재생될 수 있음
- 다시 재생돼도 좌표·경로·다음 상태는 변경되지 않음
- 전환 상태가 아니면 정적 PNG만 표시
- WFF에서 실제 `ON_VISIBLE`·분 경계 동작을 검증한 뒤 최종 트리거 확정

---

## 16. 고정 난수와 다음 장면 결정

입력 후보:

- `YEAR`
- `DAY_OF_YEAR`
- 시간 구간
- 장면 주기 번호
- 큰·작은 까치 교대 순번

금지:

- 화면을 켤 때마다 다른 장면
- 같은 분에 다시 열었을 때 위치 변경
- 걷는 중 경로 변경
- 바늘을 타는 중 다른 바늘로 갈아탐
- 장면 중간 까치 종류 변경

---

## 17. AGIF 공통 규격

- 길이: 0.4~1.2초
- 프레임: 6~12
- 속도: 약 6~10fps
- 배경: 투명
- 재생: 전환 상태에서 한 번
- 마지막 자세: 대응 정적 PNG와 연결
- 크롭: 움직이는 부분 주변 최소 영역과 안전 여백
- 기준점: 발 또는 출발점 고정
- 반전: 발 기준점 중심

전체 450×450 애니메이션이나 1254×1254 애니메이션을 런타임 자산으로 저장하지 않는다.

---

## 18. 좌표와 장면 기하 명세

애니메이션 제작 전에 다음 좌표를 450×450 논리 좌표계로 측정한다.

```text
pineSpawnLarge
pineSpawnSmall
plumSpawnLarge
plumSpawnSmall
hourHandPerchCandidates
minuteHandPerchCandidates
tigerPerchLarge
tigerPerchSmall
plumWalkWaypointsLarge
plumWalkWaypointsSmall
screenExitRight
```

좌표 명세에는 다음을 포함한다.

- 기준점 x, y
- 발 기준점
- 기본 바라보는 방향
- 허용 크롭 영역
- 렌더링 슬롯
- 앞을 가리는 가림막
- 다음 점까지의 이동 종류

좌표는 이미지 파일명이나 프레임 내부의 눈대중 위치에 숨기지 않고 별도 명세로 관리한다.

---

## 19. 렌더링 슬롯과 순서

```text
1. 배경
2. 지면·매화 경로 까치 슬롯
3. 매화·소나무·호랑이 몸 전경 가림막
4. 시침 가지
5. 분침 가지
6. 바늘 위 까치 슬롯
7. 호랑이 머리
8. 호랑이 머리 위 까치 슬롯
9. 호랑이 눈동자·반응 슬롯
```

한 까치를 여러 높이에 동시에 그리지 않는다. 현재 상태에 따라 지면·바늘·호랑이 슬롯 중 정확히 하나만 활성화한다.

---

## 20. 메모리와 AOD

목표 예산:

```text
대화형 모드: 60MB 이하 목표, 공식 한도 100MB
AOD: 8MB 이하 목표, 공식 한도 10MB
```

- 애니메이션은 모든 프레임의 압축 해제 크기를 기준으로 계산
- 투명 여백과 전체 캔버스 프레임 금지
- 동일 이미지는 중복 저장하지 않고 참조 재사용
- 큰·작은 까치의 정적·애니메이션 자산별 예상 메모리 표 작성

### AOD 정책

- 모든 AGIF 숨김
- 까치와 호랑이의 세부 레이어 최소화
- 가지 형태의 시간 표시와 필요한 최소 윤곽만 유지
- 점등 픽셀 15% 이하를 목표로 별도 AOD 그룹 구성
- 대화형 ↔ AOD 전환 시 위치 점프와 잔상 검증

---

## 21. 구현 우선순위

### 0순위: 정적 기반과 좌표

1. 기존 레이어와 다른 분리 예시 비교
2. 큰·작은 까치 역할 매핑
3. 정적 자세 6개 분리
4. 전경 가림막 3개 분리
5. 450×450 좌표·발 기준점·착석점 측정
6. 원본 정렬 레이어와 런타임 크롭 자산 파이프라인 구성

### 1순위: 큰 까치 대표 경로 수직 완성

```text
large fly_pine_to_hand
→ large land_on_hand
→ large perch_hand
→ 실제 WFF 연결
→ 에뮬레이터 검증
```

### 2순위: 작은 까치 대표 경로

큰 까치에서 검증한 기준점·트리거 구조를 사용하되 단순 축소하지 않는다.

### 3순위: 매화와 호랑이 이동

```text
large/small walk_step
large/small hop_to_tiger
```

### 4순위: 퇴장과 반응

```text
large/small fly_out_right
tiger_reaction
```

### 5순위: 전체 시간표와 최적화

- 고정 난수
- 전체 장면 결정식
- 연간 시뮬레이션
- AOD
- 메모리 최적화
- 실기기 배터리 검증

## 22. 자동 시뮬레이션

최소 검증 범위:

- 하루 1,440분
- 평년 전체 525,600분
- 윤년 2월 29일
- 12월 31일 → 1월 1일
- 시간대 변경
- 수동 시간 전진·후진
- 장시간 화면 꺼짐 후 복원
- 대화형 ↔ AOD 전환

필수 불변조건:

```text
화면에 까치 최대 1마리
활성 렌더링 슬롯 정확히 1개
착석점과 이동 좌표가 화면 안
장면 중 경로·바늘·까치 변경 없음
전환 전후 허용되지 않은 순간이동 없음
RIDE_HAND 최대시간 준수
모든 경로가 퇴장과 HIDDEN으로 종료
큰·작은 까치 교대 유지
```

## 23. 완료 단계

```text
1. 시안 제작 완료
2. 자산 검수 완료
3. WFF 연결 완료
4. 에뮬레이터 검증 완료
5. 실기기 구현 완료
```

### 자산 검수 완료 조건

- 실제 파일 존재
- 투명 배경 정상
- 프레임 잘림 없음
- 발·머리 기준점 유지
- 마지막 프레임과 정적 자세 연결
- 좌우 반전 시 위치 점프 없음

### 구현 완료 조건

- 상태 전환 전후 순간이동 없음
- 큰·작은 까치 오교체 없음
- WFF 실제 재생
- Wear OS 에뮬레이터 확인
- 가능하면 실제 갤럭시 워치 확인

정적 이미지나 미리보기 GIF만 만든 경우 `애니메이션 구현 완료`라고 보고하지 않는다.

## 24. 현재 구현과 앞으로의 범위

### 현재 MVP에서 확인된 것

- 기본 호작도 배경
- 소나무 가지 형태 시침·분침
- 시간에 따른 바늘 회전
- 바늘 위 까치 방향 보정과 좌우 반전
- 호랑이 머리와 눈동자 레이어

- 정적 자세 6개
- 전경 가림막 3개
- 무상태 장면 계산기

- 현재 시각 기반 거시 장면 복원
- 다음 장면 결정값 선계산

## 25. 조정이 남은 항목

다음 값은 구현하며 직접 보고 조정한다.

- 바늘 자연스러움 점수
- 시침 장기 장면 유지 여부
- 상태별 정확한 분 수
- 매화 경로 좌표와 칸 수
- 호랑이 체류시간
- 호랑이 반응 종류와 확률
- `hop_to_tiger` 공용 여부
- 호랑이 머리와 까치의 세부 앞뒤 순서
- AGIF의 최종 프레임 수와 fps

이 값들은 예시를 그대로 확정하지 않고, 실제 분리 자산·WFF·에뮬레이터 화면을 기준으로 결정한다.
